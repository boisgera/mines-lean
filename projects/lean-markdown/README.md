Lean Markdown
================================================================================

Introduction
--------------------------------------------------------------------------------

A Lean source file can tell a story: some prose to explain the ideas and some
code to implement them. Lean already has a place for this prose, the
module documentation comments, delimited by `/-!` and `-/`.

The idea of the Lean Markdown project is to turn such a Lean file into a
Markdown document that can be read on its own, for example on GitHub. If you
have a local file `Lemon.lean`

```lean
/-!
I ❤️ lemons!
-/

def lemon := "🍋"
```

invoke `lean-markdown` to generate the corresponding file `Lemon.lean.md`:

````bash
$ lean-markdown Lemon.lean
$ cat Lemon.lean.md

I ❤️ lemons!

```lean4
def lemon := "🍋"
```
````

The prose is left unchanged and the code ends up in Markdown code blocks.

Preparation
--------------------------------------------------------------------------------

Have a look at [the comments section of the Lean reference manual][Lean Comments].
What are the differences between the comments that start with `/-`, `/--`
and `/-!`? How do they end?

Study [the fenced code blocks section of the CommonMark specification][Fenced Code Blocks].
What is the role of the word that follows the opening fence?

Convert a small Lean file to Markdown by hand and write down the rules that you
have applied. What happens to the lines that hold only the `/-!` and `-/`
markers? To the blank lines between a comment and the code that follows it?

Lean development
--------------------------------------------------------------------------------

Start a Lean `exe` project named `lean-markdown`.

### Blocks

A Markdown document generated by `lean-markdown` is a sequence of blocks of text
(the prose) and blocks of code. Use the following types to represent the blocks
and to remember which kind of block is being read:

```lean
inductive Block where
| text (string : String)
| code (string : String)
deriving Repr, BEq

inductive State where
| text
| code
deriving BEq
```

Also define the markers of the module documentation comments:

```lean
def openMarkdown := "/-!"
def closeMarkdown := "-/"
```

### Flushing lines

The source file will be read line by line. Lines are stored in a buffer until
the current block is over; since adding an item at the head of a list is
cheap, both the buffer and the list of blocks are kept in reverse order.

Develop a function that turns the content of the buffer (if there is any) into a
new block, adds it to the blocks and empties the buffer. The `as` argument
selects the kind of block to create.

```lean
def flush (as : String -> Block) (blocks : List Block) (buffer : List String) :
  List Block × List String :=
  sorry
```

```lean
#guard flush (as := Block.code) [] [] == ([], [])
#guard flush (as := Block.code) [] ["b", "a"] == ([.code "a\nb"], [])
#guard flush (as := Block.text) [.code "x"] ["a"] == ([.text "a", .code "x"], [])
```

### Parsing

Develop a function that splits a Lean source into blocks.

```lean
def parse (source : String) : List Block :=
  sorry
```

To keep things simple, a marker is recognized only when it is alone on its line,
without any indentation. A source starts in the `code` state:

```lean
#guard parse "def a := 1" == [.code "def a := 1"]
#guard parse "/-!\nHello\n-/" == [.text "Hello"]
#guard parse "/-!\nHello\n-/\ndef a := 1" == [.text "Hello", .code "def a := 1"]
#guard parse "def a := 1\n/-!\nHello\n-/" == [.code "def a := 1", .text "Hello"]
#guard parse "/-! Hello -/" == [.code "/-! Hello -/"]
```

Module documentation is not the only thing that the `-/` marker can close.
Use the current state to make sure that the other comments stay in the code:

```lean
#guard parse "/--\nDoc\n-/\ndef a := 1" == [.code "/--\nDoc\n-/\ndef a := 1"]
#guard parse "/-\nNote\n-/\n/-!\nHello\n-/" == [.code "/-\nNote\n-/", .text "Hello"]
```

### Cleaning up

The blank lines that surround the code would end up inside the Markdown code
blocks, and those that separate two comments would create empty code blocks.

Develop a function that removes the leading and trailing whitespace of the code
blocks and then removes the code blocks that are empty. The text blocks are left
unchanged.

```lean
def cleanUp (blocks : List Block) : List Block :=
  sorry
```

```lean
#guard cleanUp [] == []
#guard cleanUp [.code "\n\ndef a := 1\n"] == [.code "def a := 1"]
#guard cleanUp [.code "\n \n", .text "Hello"] == [.text "Hello"]
#guard cleanUp [.text "\nHello\n"] == [.text "\nHello\n"]
```

### Markdown rendering

Develop a function that generates the Markdown document. Every block starts and
ends with a newline, and the code blocks are fenced and tagged as `lean4`.

```lean
def toMarkdown (blocks : List Block) : String :=
  sorry
```

```lean
#guard toMarkdown [] == ""
#guard toMarkdown [.text "Hello"] == "\nHello\n"
#guard toMarkdown [.code "def a := 1"] == "\n```lean4\ndef a := 1\n```\n"
#guard toMarkdown [.text "Hello", .code "def a := 1"]
  == "\nHello\n\n```lean4\ndef a := 1\n```\n"
```

Check that all the steps work together:

```lean
#guard ("/-!\nI ❤️ lemons!\n-/\n\ndef lemon := 1\n" |> parse |> cleanUp |> toMarkdown)
  == "\nI ❤️ lemons!\n\n```lean4\ndef lemon := 1\n```\n"
```
